## Notes

The probe (`scripts/nitya-token-probe.py`, `nixosModules.token-probe`) runs on ghost001 as
a systemd timer every 6 hours, wired by neusis's `features.nixos.nitya-token-probe` to the
owner's tokens from `nitya-consent` (agenix, `/run/agenix/nitya*`). Each check refreshes
and reads a little, and appends a line to `/var/lib/nitya-token-probe/probe.jsonl`:
- Google: the Production, unverified client of the `nitya-oauth` project (prediction 1).
- Microsoft, two chains (prediction 3): `latest` keeps each rotated refresh token in the
  probe's state, as nitya's server would; `original` refreshes the bootstrap token every
  time, to see whether it alone would last.
- iCloud: the app-specific password (not in the plan; cheap to watch).

`collect.sh` copies the log over the tailnet and summarises it; run it any time and at
day 30. The 30 days count from the first check on ghost001.

Before deploying, one check ran on rogue against the real accounts (not part of the run):
all four chains worked and Microsoft rotated its token on refresh.

Not run: prediction 2's control, a second Google client left in Testing. It needs a
second project (publishing status is per project), its consent screen and client made by
hand, and a consent; added if the owner wants it.

Not controlled: the providers' policies over the month; ghost001's uptime and network
(missed checks are caught up by `Persistent=true`); the owner revoking or re-consenting.
