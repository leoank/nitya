## Notes
On rogue, 2026-11-26, on the leoank tailnet with the owner's existing reusable key (neusis
`leoankTsAuthKey`, here `~/.config/sandhi/leoank-authkey`); every node joined ephemeral
and dropped off on its own. Node ids, keys, addresses and the tailnet's DNS suffix are
placeholders in `out/` (the repo is public); the comparison was made on the real values.
The key's path is passed as `AUTHKEY_FILE` and not recorded as env.

| call | host | DNS name | node id | node key | address |
|------|------|----------|---------|----------|---------|
| A joins | nitya-idtest-node | nitya-idtest-node | id-1 | key-1 | addr-1 |
| A restarts, same state | nitya-idtest-node | nitya-idtest-node | id-1 | key-2 | addr-1 |
| B joins, fresh state, A's hostname | nitya-idtest-node | nitya-idtest-node-1 | id-2 | key-3 | addr-2 |
| A again | nitya-idtest-node | nitya-idtest-node | id-1 | key-4 | addr-1 |

- P1 holds: the server's status gives the node id and key for the connection's address.
- P2 holds for the id and the address; the node key does **not** survive a restart (new
  on every start, for an ephemeral node). Not tested for a non-ephemeral node: that would
  leave machines on the owner's tailnet to remove by hand, and the binding does not use
  the key either way.
- P3 holds: B gets a new id, key and address. Its requested hostname is the same as A's;
  the tailnet renamed only its DNS name (`-1`). The hostname is a label, not an identity.
